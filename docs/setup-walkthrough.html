Atelier · getting started

Set up your design studio

Choose a local model, connect a cloud route, or use your ChatGPT plan through OpenAI’s official sign-in. This walkthrough takes you from installation to a first design question, with the limits visible at each step.

Part one

Install Atelier

For: anyone setting up the public preview, whether the model runs locally or through a hosted endpoint.

You need: Node.js 24, pnpm 10 or newer, an Atelier folder, and one of the model routes in the next sections.

  1. Install Node.js 24 and pnpm 10+.
  2. In the Atelier folder, run pnpm install --frozen-lockfile. This installs JavaScript packages; it does not download a model.
  3. For a compatible endpoint, set ATELIER_BASE_URL and ATELIER_MODEL on the first run. For a cloud route, use ATELIER_PROFILE=cloud as described below.
  4. Start with pnpm start. Add -- --open to open the browser. The web app uses port 3081 by default.
  5. Choose a workspace folder, select the Vitruvius profile, and ask a design question.

How you know it worked

The app opens at its local address, accepts a workspace, shows Vitruvius, and returns an answer to a design question.

Honest limits

Atelier ships no model. Your selected endpoint must be running and serve the model ID you configured. IngeTrazo is optional and installed separately.

Part two

Choose a local model setup

For: people who want an AI endpoint on hardware they control. The 32 GB and 16 GB rows reflect measured configurations; the 8–12 GB row is guidance only.

You need: a compatible local model server, its base URL and model ID, and a model whose weights, context and vision support fit your hardware. For Atelier’s first local run, set ATELIER_BASE_URL and ATELIER_MODEL.

Set up the local route

  1. Choose the row that matches your GPU memory; treat the 8–12 GB row as guidance, not a measured preset.
  2. Install and start a compatible model server for that choice, then note its OpenAI-compatible base URL and served model ID.
  3. On the first Atelier run, set ATELIER_BASE_URL and ATELIER_MODEL to those values. Set ATELIER_CONTEXT if you need a context value other than the documented 32,768 default.
  4. Run pnpm start, choose a workspace and Vitruvius, and send a design question.

Serving engines at a glance

Intel brain

vLLM built for Intel XPU in the measured 32 GB configuration.

GGUF models

llama.cpp with CUDA, Vulkan or SYCL; llama.cpp server, LM Studio and Ollama are compatible endpoint options.

Speech and recall

Parakeet TDT 0.6B v3 uses Q4_K GGUF through parakeet.cpp; CPU is measured at about 5× real time and about 0.6 seconds per short clip. EmbeddingGemma is optional; Atelier works without it.

How you know it worked: the model endpoint responds, Atelier accepts the configured model ID, and Vitruvius answers a design question. Optional vision works when you attach an image to a vision-capable model; optional sidecars have separate availability checks.

Limits: the 32 GB and 16 GB rows are specific measured setups, not universal performance guarantees. The 8–12 GB suggestion is unmeasured guidance. Context length, model fit, quantisation and speed depend on the chosen hardware and server. Image service is bring-your-own and optional.

Part three

Run cloud-only through OmniRoute

For: people with no local model GPU, or anyone choosing hosted models for Atelier. Atelier and connected design software run locally; AI requests go to the cloud providers you connect.

You need: an internet connection and at least one provider account and key. Free provider tiers are available, but each requires its own account and key. You can add paid API keys you already own after free choices.

  1. Install OmniRoute with npm install -g omniroute, then run omniroute. Open its dashboard at http://localhost:20128.
  2. Add provider keys in the dashboard. Free-first options in the verified setup: Google AI Studio (Gemini API), OpenRouter models ending in :free, Groq, Cerebras, Mistral’s free Experiment tier, NVIDIA trial credits, and Cloudflare Workers AI’s daily allocation. Trial credits can run out. Skip providers whose terms forbid this use.
  3. Optionally connect paid keys you already own, such as OpenAI, Anthropic, DeepSeek, xAI or OpenRouter credit. The three combos prioritize free providers and put paid choices last; disconnected providers are skipped.
  4. In the Atelier folder, run node profiles/cloud/setup-omniroute-combos.mjs to create the three combinations below.
  5. Start Atelier with ATELIER_PROFILE=cloud pnpm start. The launcher starts a local bridge; the bridge starts OmniRoute on the first cloud request.
  6. Choose a workspace and Vitruvius, then send a real design question. The brain is the default route; fast and vision routes are available for their roles.

How you know it worked: a real Atelier chat returns a reply. In the measured setup with only a free Gemini key and OpenRouter free models, OmniRoute returned a plain brain reply in 3.2 s and a tool call in 2.9 s; fast replies took 0.85 s and tool calls 0.89 s; the vision route read a test image correctly in 2.8 s. A real Atelier chat turn took 16.6 s including opening the chat. A real tool task completed with 2 of 2 tests passing.

Limits: free tiers have per-minute and per-day caps; a large context model can still hit tokens-per-minute limits. System 1 adapter and embeddings are absent from this cloud profile, so Atelier falls back to the brain. Speech stays optional and local. Cloud prompts and files sent to providers leave your office; keep confidential client work on a local model. Cloud images need a supported provider key or trial allocation; the ChatGPT-plan route does not generate images.

Cloud image option: set ATELIER_IMAGE_ENDPOINT to the bridge’s /omniroute/v1/images/generations route and set ATELIER_IMAGE_MODEL. Image generation is optional; provider availability and terms apply.

Part four

Use your ChatGPT plan

For: people with a ChatGPT plan who want to connect a locally running app using OpenAI’s official Sign in with ChatGPT preview for open-source apps.

You need: Atelier’s cloud profile, a browser, and a ChatGPT account with a plan. This is the documented OpenAI sign-in route; it is not a token hack or the Codex backend.

  1. Start Atelier with ATELIER_PROFILE=cloud pnpm start.
  2. Open http://127.0.0.1:18345/signin in your browser.
  3. Sign in to ChatGPT, choose your workspace, and approve “use my ChatGPT plan” for the app named Atelier.
  4. Confirm the page says “Connected to ChatGPT.” The local status page is http://127.0.0.1:18345/status and does not show tokens.
  5. In Atelier’s model picker, select a model under “ChatGPT plan”: GPT-6 Luna or GPT-6.1 Sol, with no reasoning (@none), low, medium or high.
  6. Ask a text question. You can also provide images or files as input.

How you know it worked: the sign-in page reports Connected to ChatGPT, the model appears in the picker, and Atelier returns a reply. Timings: to be measured. This route has not yet been measured end to end, so no timing is claimed.

Limits: usage counts against your ChatGPT plan. Plus has a shared five-hour limit across apps; review or limit usage in ChatGPT Settings · Usage. OpenAI’s preview route supports text plus image and file inputs, but not image generation, file search, code interpreter or hosted MCP. The bridge runs on your computer, stores sign-in data in a private home-folder file, refreshes automatically and does not log tokens.

Official references: Sign in with ChatGPT for open-source apps · Sign in with ChatGPT cookbook.

Engineer appendix

Under the hood

This appendix collects the configuration details needed to debug setup. The designer steps above are sufficient for a first chat.

Request shaping and security

  • The bridge follows OpenAI’s documented preview rules: store=false, streaming enabled, and unsupported fields removed (including temperature, max_output_tokens and previous_response_id).
  • A system role is sent as developer. If a route asks for it, tools are grouped into a namespace. A model name ending in an “@effort” suffix maps to reasoning.effort.
  • The bridge listens on loopback only; cross-site browser requests are refused. A client key is optional.
  • ID token signatures are checked against OpenAI’s published keys. Refresh tokens rotate and are stored atomically. Sign-out revokes the session.

Troubleshooting

Sign-in callback port is busy

The bridge tries port 1455, then 1456–1459. Close the process using the callback port or let the documented fallback be used, then retry sign-in.

Free-tier rate limit

A provider may enforce per-minute or per-day limits, including token limits. The combo skips disconnected providers instantly; connect another free provider or add a key you already own, then retry.

OmniRoute is not running

Start omniroute and check its dashboard at http://localhost:20128. The Atelier bridge can start OmniRoute on the first cloud request; if that does not happen, check ATELIER_OMNIROUTE_START.

Local endpoint or model ID fails

Check that the model server is running, the base URL ends with /v1, and the configured model ID matches one reported by that endpoint.
